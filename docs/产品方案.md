# 安响：独居老人意外风险发现与社区处置方案

## 1. 要解决的问题

独居老人跌倒或长时间失去活动能力时，可能无法主动打电话或按下报警器。家属不可能持续陪伴，社区网格员也难以逐户高频查看。安响希望把“有人发现异常”提前到老人主动求助之前，并让后续联系、核实、上门与结案有迹可循。

本项目目前处于**概念和网页原型阶段**。现有演示页面只说明交互与处置思路，尚未验证传感器识别能力，也未接入真实社区业务。

## 2. 服务对象与定位

主要服务对象是独居或白天独处的老人；直接使用者是负责相应社区的网格员。家属是需要时接收通知和反馈的协作方。系统输出的是**待核实的风险事件**，由人决定后续处置，不做医疗诊断。

产品主线：非影像化活动信号 → 识别异常 → 展示依据与风险等级 → 网格员联系、核实或上门 → 记录结果。

感知方式可研究红外、毫米波雷达等，但具体设备、可得字段与准确度尚未确定。不采集图像和持续录音是设计方向，是否可实现仍取决于实际选型。

## 3. 场景取舍

| 层级 | 场景 | 处理方式 |
| --- | --- | --- |
| 核心 | 疑似跌倒 | 有相应设备事件时，提示网格员尽快核实；持续无回应可升级。 |
| 核心 | 异常长时间静止 | 对照个人常态、时间段和信号完整性，形成待核实提醒；不能单凭一次“没活动”断定意外。 |
| 辅助 | 老人主动求助 | 若接入求助设备，直接进入联系与处置流程。 |
| 后续扩展 | 燃气等明确的居家安全告警 | 可复用事件展示与社区处置流程，但需独立设备、规则和责任划分。 |
| 暂缓 | 用水、用电等日常异常 | 先不作为当前版本的核心能力或演示结论。 |

异常卧床可视为“异常静止”的一种具体情形，先不单独扩张为完整产品线。正常睡眠、离家、设备离线或数据中断都可能造成误判；缺少个人基线时，不应声称识别了“习惯偏离”。

## 4. 最小可验证流程

1. 设备或模拟数据上报活动事件，带住户映射、时间和设备状态。
2. 系统结合时间段、历史常态与信号完整性生成待核实事件，展示判断依据和不确定之处。
3. 网格员在列表或社区空间图中定位住户，查看同一事件详情。
4. 网格员联系老人或家属；联系不上时，按既有社区规则安排上门或升级。
5. 记录处理人、时间、动作、结果和原因。误报也应留痕，供后续调整规则。

风险等级可采用“关注、需尽快核实、紧急”。具体阈值、升级条件与通知对象须由设备能力、试点数据和社区职责共同确定，此阶段不编造固定时长。

## 5. 网页原型与真实产品的边界

现有网页原型已提供简化三维社区、楼栋与楼层交互、告警列表、住户位置定位、事件详情和模拟处置按钮。五栋楼及事件均为虚构；按钮只改变页面内的显示状态，刷新后不会保留。它适合展示网格员如何发现和打开告警，不足以证明异常识别、实时通知、权限控制或完整结案流程已经实现。

真实系统仍需住户与设备映射、数据接入、设备离线提示、事件去重、权限控制、联系记录、派单及审计记录。展示数据应与真实个人信息严格区分。

## 6. 下一步验证

优先确认可用设备与数据字段，再用小范围、经授权的数据验证两件事：一是正常休息与异常静止能否区分；二是网格员看到提醒后，能否根据依据判断下一步动作。至少记录误报、漏报、响应时间和处置结果。网页原型可用于访谈和流程演练，不能代替真实识别效果评估。
